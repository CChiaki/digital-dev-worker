# 备份恢复演练手册

> 2026-09-11 P2 产品批新增。目标是「备份真的能恢复」——每季度演练一次，演练记录留档。

## 1. 备份对象清单

| 对象 | 内容 | 备份方式 | 说明 |
| --- | --- | --- | --- |
| 业务库 | MySQL/OceanBase 全部 `ddw_*` 表（任务/事件审计链/员工/渠道/Skill/消息） | `mysqldump --single-transaction ddw > ddw-$(date +%F).sql` | **事件表（ddw_events）是审计合规红线，不可删减**；sqlite 部署直接停服拷 dataDir |
| runtime-local.yaml | 运行时配置（含 enc:v1 密文） | 文件级拷贝 | 密文依赖主密钥才能解开——**yaml 与密钥分开存放** |
| 主密钥 | `DDW_CRED_KEY` 环境变量值 | 纸质/密码库专人保管（pm2 `pm2 save` 的 dump 文件不算备份） | **丢失 = 库内 enc:v1 渠道密钥与员工模型 key 永不可解**，只能全部重录 |
| 前端产物 | `<部署目录>/ui` | 随包备份 | 丢失可从源码 `vite build` 重建，非关键 |
| 任务工作区 | workspaceRoot 下 git clone 与中间产物 | **不备份**（done 任务按 retention TTL 清理，产物在代码托管上） | — |

## 2. 恢复演练步骤（异机/本机重放）

1. **恢复库**：建空库 `ddw-restore` → `mysql ddw-restore < ddw-备份日期.sql`。
2. **改配置指向恢复库**：拷 runtime-local.yaml，storage.url 指向 `ddw-restore`（端口避让 3100，如 `--port 3200`）。
3. **注入主密钥**：`DDW_CRED_KEY=<纸质/密码库取回> node --import packages/console-api/src/team/ts-register.mjs packages/console-api/src/cli.ts --port 3200 --data <临时dataDir>`。
   主密钥错误不会启动报错（密文只在发送/解密现场用），必须走下面第 5 步验证。
4. **验证任务面**：`GET /api/tasks` 任务列表齐全；任选一单 done 任务 `GET /api/audit/:taskId` 时间线完整。
5. **验证密文可用**：控制台「通知渠道」页对恢复渠道点「发送测试消息」——发送成功 = 主密钥正确 + 密文完好；失败（解密错误）= 密钥不对，回第 3 步。
6. **验证审计链**：`POST /api/audit/verify` 返回 `ok: true`（hash 链全链校验）；或控制台「审计台账」页徽标绿 + 「立即校验」。
7. **验证调度**：提交一单小任务（echo 类）走完 done——确认执行链路（模型网关/工作区/事件回流）整体健康。
8. **收尾**：停掉演练进程，删临时库与临时 dataDir，记录演练日期与结论。

## 3. 常见恢复坑

- **恢复库里有 claimed/running 任务**：首次启动孤儿扫描会自动标 failed「进程重启中断」（可续跑/重置），属预期行为，不是数据损坏。
- **事件 hash 链校验失败**（`ok: false`）：说明备份/恢复过程中事件行被改动或丢失——从更早的全量备份重放，不要手工补行（链是连续 hash）。
- **pm2 环境变量丢失**：`pm2 restart --update-env` 不带 DDW_CRED_KEY 时进程内密钥为空，渠道发送将报解密错误——恢复演练第 3 步必须显式注入验证。
