# 任务指定员工分派（assignee）设计

日期：2026-09-06 ｜ 状态：已与用户对齐，待实施

## 需求

发布任务时可以指定某个数字员工执行：
- **不指定** → 按现有调度逻辑（岗位匹配 + 依赖编排）；
- **指定** → 任务分派给该员工；员工当前有任务时，等其完成后自动执行（排队）。

已确认决策：**指定员工优先，忽略岗位匹配**；**指定员工不存在/停用时任务留池、调度留痕等人工处理**（不在发布时拦截）。

## 现状探查结论（2026-09-06）

- 调度器 `TeamScheduler.tickInner` 仅处理 `pending` 任务：依赖 readiness → `ManagedRoster.acquire(role, canDispatch)` 按岗位挑**空闲**员工 → `tasks.claim` 原子接单。
- **员工独占**：`free.delete(id)`，同一员工同时最多 1 个任务；`release` 在任务完成时归还。
- **忙 = 天然排队**：acquire 返回 null → 任务留 pending 池、记 waiting 留痕，下一 tick（5s）重试。指定员工只需把 acquire 换成「点名」，排队语义免费获得。
- `parseTaskPackage` 是**白名单拼装**返回值——新增字段必须改 `TaskPackage` 接口 + 校验 + return 拼装，否则静默丢弃。
- 前端 yaml 原样透传（POST /api/tasks → parseTaskPackage），存储层存 pkg JSON 原样，无需迁移。

## 设计

### 1. runtime：任务包字段 `assignee`

- `TaskPackage` 新增 `assignee?: string`（员工 id，可选）；
- `parseTaskPackage`：可选字段校验——存在则必须为**非空字符串**（trim 后），错误信息模型可读（沿用 `role` 校验模式）；白名单拼装加入 `assignee`；
- `assignee` 与 `role` 可共存，语义上 assignee 优先（校验不做互斥）。

### 2. 调度器：点名分派

- `ManagedRoster` 新增 `acquireById(id)`：员工存在、启用且 `free.has(id)` 时占用并返回；否则返回 null；
- `scheduler.tickInner`：`pkg.assignee` 存在 → `acquireById(pkg.assignee)`，**跳过 role 匹配**；返回 null → 任务留池并留痕：
  - 员工不存在/停用 → `waiting: 指定员工不可用（{id}），等人工处理`；
  - 员工正忙 → `waiting: 指定员工 {id} 正忙，完成后自动分派`；
  - 留痕去重沿用现有 note 机制；
- 依赖 readiness 判定**不变**（dependsOn 逻辑与 assignee 正交，先过依赖关再点名）；
- 点名路径**有意跳过 `canDispatch` 能力过滤**（终审留痕）：点名即人工显式意志，即使员工 capabilities 未绑定该 plan kind 也接单，避免点名任务被能力过滤卡死。

### 3. 前端：创建表单「指定员工」下拉

- `TaskCreateDialog` 表单模式新增「指定员工（可选）」`el-select clearable`：选项 = `GET /api/employees` 员工（`id + name` label，**排除停用**——新建任务不应指定停用员工；加载失败不阻塞，可清空不选）；打开对话框时与 employees 拉取合并（T5 已有该请求，复用同一 Promise.all）；
- `task-form.ts` 四处：`TaskFormState.assignee?: string`、`planFormToYaml`（空不出键）、`yamlToPlanForm`（反填）、确认**不进 `LEGACY_FIELDS`**；
- 指定员工与岗位可同时填写，运行时 assignee 优先（表单不加联动禁用，保持简单）。

### 4. 展示

- `TaskDetail` descriptions 新增「指定员工」行（无则不显示该行或显示 —，与相邻行风格一致）；
- 任务中心列表不加列（接单后「领取人」列自然显示）。

## 错误处理

| 场景 | 处理 |
|---|---|
| 指定员工不存在/停用 | 调度留痕「指定员工不可用」，任务留池等人工（改包重发或恢复员工） |
| 指定员工正忙 | 留痕「正忙，完成后自动分派」，tick 自动重试 |
| 员工列表拉取失败 | 下拉为空不阻塞表单（可清空不指定） |
| yaml 手写 assignee 非法（空串/非字符串） | parseTaskPackage 校验报错，错误信息可读 |

## 测试

- runtime：parse 校验（合法/空串/非字符串/缺省）；
- scheduler：指定员工直接分派（忽略 role，员工 skills 不含任何岗位也能接）；指定员工忙 → 留池 waiting 留痕，员工 release 后下一 tick 分派；指定员工不存在 → 留痕不可用；指定 + dependsOn 组合（依赖未 done 不点名）；
- roster：acquireById 占用/释放/停用/不存在；
- 前端：task-form 往返序列化（assignee 含/不含）；TaskCreateDialog 选项来源（排除停用）与提交 yaml 含 assignee；TaskDetail 指定员工展示；
- 回归：四包 vitest + vue-tsc 全绿。

## 不做的事（YAGNI）

- 不做发布时校验员工状态（运行时留痕即可）；
- 不做「改派/取消指定」编辑功能（改 = 重新创建任务）；
- 不做指定员工队列深度/优先级；
- 任务中心列表不加列。
