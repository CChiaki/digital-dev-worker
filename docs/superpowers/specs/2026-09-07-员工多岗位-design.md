# 员工多岗位 设计（2026-09-07）

## 背景与目标

刚收官的「岗位管理即技能库」为单岗位模型（`role: string`）：全栈员工接不到另一岗任务，行内试点员工少、一人多角是常态。目标：

- **员工可挂多个岗位**（roles 数组），岗位仍是受管清单（SkillCategory，复用现状）
- **多岗位决定「能不能接单」**：`pkg.role ∈ emp.roles` 即可分派
- **任务岗位决定「带什么知识」**：注入按任务 pkg.role 过滤（只带该岗位 skill），任务无岗位才用全部岗位并集——避免全栈员工写前端页面还背着后端规范

## 核心决策

### D1：EmployeeRecord.role → roles: string[]

```ts
interface EmployeeRecord {
  id: string;
  name: string;
  roles: string[];          // 岗位名数组（2026-09-07 多岗位）；每项须是已注册岗位 name
  // …其余字段不变
}
```

- **兼容读取**：旧 `role: "后端开发"` 读入包装为 `roles: ["后端开发"]`；旧 `skills`/`skillCategories` 继续忽略
- 校验：`roles` 非空数组、每项非空字符串、白名单非空时每项都须在岗位名清单中（400 列出可选岗位）；至少一个岗位（员工必须有归属岗，防止「永不匹配」的孤儿档案）
- `EmployeeProfile.role`（runtime 类型）不动：取 `roles[0]` 作展示主岗

### D2：调度 = 任务岗位 ∈ 员工岗位集合

`ManagedRoster.acquire(role)`：`if (role && !r.roles.includes(role)) return false;`

- 任务 pkg.role 空 → 不过滤（任何空闲员工可接）——现状语义不变
- 点名 assignee（acquireById）绕过岗位匹配——现状语义不变
- EmployeeRoster（runtime yaml 回退路径）不动

### D3：注入 = 按任务岗位过滤，无任务岗位才并集

`skillsFor` 签名扩展：`(employeeId: string, taskRole?: string) => Promise<SkillRecord[]>`

装配层语义（server.ts）：

```
员工 roles → 查每个岗位名对应分类 → approved skills
├─ taskRole 非空且 ∈ 员工 roles → 只取 taskRole 对应分类（精准注入）
├─ taskRole 非空但 ∉ 员工 roles（点名分派等路径）→ 并集兜底
└─ taskRole 空 → 全部岗位并集
```

- 两个消费点同步传参：inproc `executor.ts` 传 `task.pkg.role`；fork `process-executor.ts` 分派时刻同样传（快照语义不变，只是快照按任务岗位预过滤）
- `plan-runner` / `worker` / 注入指令组装（appendSkillContext/materializeSkillAssets）**零改动**——它们只消费最终 skill 清单
- fork 快照注记：job.config.skills 语义变为「该任务岗位过滤后的清单」（分派时刻定格）

### D4：前端岗位改多选

- 员工编辑对话框：岗位 el-select `multiple`（数据源不变 = 分类清单 name）；至少选一个（表单校验）
- 员工列表/详情：岗位列展示 tags（多值）；TaskCreateDialog 不变（单选任务岗位）
- GET/POST/PUT 员工 API：`role` 字段换 `roles` 数组（前端类型同步）

## 测试要点

- 兼容读取：旧单值 role 读入 → roles 包装；旧 skills/skillCategories 仍忽略
- 校验：roles 空/含未注册岗位 400；白名单空不设限
- 调度：多岗位员工接任一岗位任务；任务岗位不在员工集合不接；点名路径不受影响
- 注入：任务岗位 ∈ 员工岗位 → 单分类精准注入；任务无岗位 → 并集；点名岗位不在集合 → 并集兜底；fork 快照同语义
- 装配层（server-assembly）锁死 skillsFor 新签名接线（防 C1 复发）
- 前端：多选提交、列表 tags、编辑回填

## 明确不做（YAGNI）

- 员工主岗/岗位权重排序（roles[0] 即主岗，仅展示用）
- skill 跨岗位复用（categoryId 仍单值；多岗位靠员工侧并集解决）
- 按计划项 kind 细粒度选岗（任务级 role 已够）
- 岗位互斥/容量规则
