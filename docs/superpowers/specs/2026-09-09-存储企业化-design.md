# 存储企业化改造（storage 配置化：sqlite / mysql 全落库）设计

> 2026-09-09 · 用户拍板：两驱动都做（本地 MySQL 验证）；json 文件存储形态从部署运行时消灭——「数据源配置了 sqlite 就全部写 sqlite，配置了 mysql 就全部用 mysql」。

## 1. 背景与问题

现状 `packages/console-api` 存储为混合形态：任务池/事件流走 sqlite（node:sqlite），员工档案/Skill 库/能力注册表/消息中心/通知渠道走 5 个 JSON 文件（`data/*.json`），任务池还有 file 实现与 `--store` CLI 参数。问题：

- **企业部署不可接受**：JSON 文件无事务、无并发保护、无备份/恢复标准方案，行内运维只认数据库。
- **配置散落**：存储选型在 CLI 参数（`--store`），不在 runtime yaml——与「一处 yaml 管部署」的企业化方向相悖。

## 2. 目标与非目标

**目标：**

1. runtime yaml 新增 `storage:` 段，`driver: sqlite | mysql` 二选一，**全部 7 个存储域**（tasks / events / employees / skills+categories / capabilities / messages / channels）落同一个数据源。
2. 缺省（无 storage 段）= sqlite + `<dataDir>/ddw.sqlite`，现有演示/试点零回归。
3. 一次性迁移命令 `cli.js migrate`：把旧形态（sqlite 任务/事件 + JSON 档案）导入目标库。
4. doctor 增加存储连通巡检。
5. mysql 凭据支持 `enc:v1:` 密文（复用 cred 主密钥机制）与明文两用。

**非目标（明确排除）：**

- `workspaceRoot` / `sessionsRoot` 仍为文件目录——员工工作区（代码文件）与 session jsonl 是**工作文件**不是存储数据，天然就是文件形态，不属于本次「存储落库」范畴。
- 不做多库分片、不引入 ORM（驱动抽象层自研，保持零重依赖风格——mysql2 除外）。
- File* 实现类**保留不删**（供 migrate 读取旧数据 + 测试对照使用），仅从装配选项中退役：`--store` 参数退役，运行时装配只有 sqlite/mysql 两分支。File 实现的最终退役删除登记为后续迭代项。
- 不做 MySQL 集群/主从语义，单实例 DSN。

## 3. 配置设计

```yaml
# runtime yaml 追加段（与 routes/forge 同级）
storage:
  driver: sqlite            # sqlite | mysql，缺省 sqlite
  sqlite:
    path: ./data/ddw.sqlite # 缺省 <dataDir>/ddw.sqlite
  mysql:                    # driver: mysql 时必填
    host: 127.0.0.1
    port: 3306
    user: root
    password: "<明文 或 enc:v1:...>"   # enc 密文经 DDW_CRED_KEY 解密（复用 resolveSecret）
    database: ddw
```

- 缺省兼容：无 storage 段 → `driver: sqlite, sqlite.path = <dataDir>/ddw.sqlite`——与现状行为完全一致。
- `--store` CLI 参数退役：传入即报错退出（中文提示改用 yaml storage 段），避免双配置源。
- mysql 配置校验：driver=mysql 而 mysql 段缺 host/user/database 任一 → 启动即失败（中文报错）。

## 4. 架构：驱动抽象层

新增 `packages/console-api/src/stores/sql/`：

```
sql/
  driver.ts        # SqlDriver 接口 + JsonCodec
  sqlite-driver.ts # node:sqlite DatabaseSync 实现
  mysql-driver.ts  # mysql2/promise pool 实现
  schema.ts        # 7 表 DDL（双方言生成）
```

```ts
export interface SqlDriver {
  /** 建表（幂等，启动时执行） */
  ensureSchema(): Promise<void>;
  exec(sql: string, params?: unknown[]): Promise<void>;
  all<T = unknown>(sql: string, params?: unknown[]): Promise<T[]>;
  /** 事务（mysql BEGIN/COMMIT，sqlite node:sqlite 无显式事务 API → BEGIN/COMMIT exec 等价实现） */
  tx<T>(fn: () => Promise<T>): Promise<T>;
  /** 方言 upsert SQL：sqlite ON CONFLICT(pk) DO UPDATE / mysql ON DUPLICATE KEY UPDATE */
  upsertSql(table: string, pkCol: string, cols: string[]): string;
  /** JSON 编解码：sqlite TEXT 存 stringify 字符串；mysql JSON 列 mysql2 返回已解析对象 */
  encodeJson(v: unknown): unknown;
  decodeJson<T>(v: unknown): T;
  close(): Promise<void>;
}
```

**关键方言差异与决策：**

| 差异点 | 决策 |
|---|---|
| 任务 claim 原子性 `UPDATE ... WHERE id=? AND status='pending'` | 标准 SQL 双方言通用，靠受影响行数判定（现状语义不变） |
| upsert | 驱动各自生成方言 SQL（接口 `upsertSql`），DAO 不写方言 |
| 事件 append 保序 + 同 id 重放容错 | 自增主键 seq 天然有序；同 id 重放 = `WHERE NOT EXISTS` 判重后跳过（双方言可写） |
| 自增列 | `AUTOINCREMENT`（sqlite，实际用 rowid 语义）/ `BIGINT AUTO_INCREMENT`（mysql），DDL 生成时分支 |
| 事务内读改写（事件 hash 链、消息滚动删除） | 全部包在 `tx()` 里 |

**连接模型**：mysql2 用 `createPool`（`connectionLimit: 10`，`namedPlaceholders: false`）；node:sqlite 单连接同步（现状即如此，Console API 单进程）。两实现都把同步/异步差异收在驱动内，上层只见 async。

## 5. 表结构（窄列 + doc JSON）

命名统一 `ddw_` 前缀。查询所需的过滤/索引列抽窄列，整条记录存 `doc` JSON 列（mysql `JSON` / sqlite `TEXT`），**存储接口（types.ts 已有的 TaskStore/EventStore + 各档案 store 方法面）完全不变**——业务代码零改动，只换装配。

| 表 | 窄列（PK / 索引 / 过滤） | doc 内容 |
|---|---|---|
| `ddw_tasks` | id PK, status(索引), claimed_by | TaskRecord（pkg/result/planProgress/claimedAt/failedItemId） |
| `ddw_events` | seq 自增 PK, id(唯一索引), ts, task_id, employee_id, type(索引), hash, prev_hash | AgentEvent 全量 |
| `ddw_employees` | id PK, enabled(索引) | EmployeeRecord（含 roles/supervision/model） |
| `ddw_skill_categories` | id PK, name(唯一索引) | SkillCategoryRecord |
| `ddw_skills` | id PK, category_id(索引), status(索引) | SkillRecord |
| `ddw_capabilities` | kind PK | CapabilityRecord |
| `ddw_messages` | id PK, read(索引), created_at(索引) | MessageRecord（1000 条滚动：add 时 tx 内 DELETE 超额） |
| `ddw_channels` | id PK | ChannelRecord |

hash 链（`verifyIntegrity`/`snapshotHead`）语义原样保留：mysql 分支快照文件仍写 `<dataDir>/audit-snapshot.json`（快照是「库外存证」，天然文件形态，与非目标同理）。

## 6. 各 store 实现策略

- **tasks/events**：现有 `SqliteTaskStore`/`SqliteEventStore` 重构为基于 SqlDriver 的 `SqlTaskStore`/`SqlEventStore`（单实现双驱动；现有测试全量保留跑 sqlite 分支）。File 实现退役出装配。
- **employees / skills / capabilities / messages / channels**：新建 Sql 实现（`SqlEmployeeStore` 等）。文件实现里的**业务规则保持纯函数复用**（校验白名单/trim/岗位名校验/distiller 去重查询等已在 store 外或可提取），Sql 实现里同样调用，杜绝两实现规则漂移。skill 的 seed（五分类）在 Sql 实现按 ensureSchema 后空表时同口径 seed。
- **装配**（server.ts）：`opts.storage.driver` 分支一次，7 个 store 按驱动构造；`dataDir` 仍用于快照/迁移标记等库外文件。

## 7. 迁移命令

`node dist/cli.js migrate [--to sqlite|mysql] [--storage <yaml>]`：

1. 读取源：旧 sqlite（`<dataDir>/ddw.sqlite`，任务/事件经 SqliteTaskStore/SqliteEventStore 读出）+ 5 个 JSON 档案文件（fs 直接读，不经 File store 类）。
2. 事务内导入目标库；目标库已有数据时**拒绝执行**（中文提示「目标库非空，拒绝迁移」防误覆盖）。
3. 成功后在 `<dataDir>/migrated-<driver>.marker` 留痕（含条数统计输出到 stdout）。
4. 旧文件**不删除不移动**（由用户确认业务正常后自行处理）。

## 8. doctor 增项

- storage 段解析校验（driver 枚举/必填字段）。
- 连通探测：sqlite 文件可写；mysql 连接 + 目标库存在 + `ddw_` 表清单（未建表提示「首次启动自动建表」不阻塞）。

## 9. 安全

- mysql password 支持 `enc:v1:`（`resolveSecret` 复用）；**明文配置不阻塞但 doctor 提示建议密文**（与模型 apiKey 同口径）。
- 测试用 MySQL 连接串只经环境变量 `DDW_TEST_MYSQL_URL`（如 `mysql://root:***@127.0.0.1:3306/ddw_test`），**任何真实凭据不入 git**（测试文件/fixture 一律 env 读取）。

## 10. 测试策略

- **双驱动矩阵**：7 个 store 的行为测试写成「驱动工厂」风格——sqlite 用 `:memory:` 必跑；mysql 分支由 `DDW_TEST_MYSQL_URL` 存在性开关（缺 env 全部 `describe.skip`，离线 CI 全绿不破）。本地验证时注入 env 跑 mysql 全量。
- claim 原子性 / 事件 hash 链 / 同 id 重放 / 消息滚动删除 / upsert 并发语义在 mysql 分支各有专属用例。
- e2e（integrated/full-chain）保持 sqlite；新增 mysql smoke e2e（env 开关）：创建→分派→完成→审计校验全链。
- `pnpm -r typecheck` 零错误；全仓既有用例零回归。
