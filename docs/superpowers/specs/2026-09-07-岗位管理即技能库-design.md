# 岗位管理即技能库 设计（2026-09-07）

## 背景与目标

现状三个概念纠缠：员工 `role`（自由文本展示名）、员工 `skills`（岗位匹配集合，调度用 `pkg.role ∈ skills`）、员工 `skillCategories`（Skill 注入开关）。用户目标模型：

- **岗位可管理**：前端开发 / 后端开发 / 测试 / 需求——可增删改
- **岗位即技能库**：每个岗位下挂对应 Skill（现有 skill 挂分类机制直接复用）
- **员工只选岗位**（下拉单选），执行时自动注入本岗位的 approved skill
- **任务发布选岗位**：岗位下拉来自岗位管理清单；调度按岗位匹配员工
- **能力（capabilities）不动**：管执行权限，与岗位/skill 分工不变

## 核心决策

### D1：岗位 = 现有 SkillCategory（复用，不新建实体）

SkillCategory（`skill-store.ts`）已有完整 CRUD + API + 分类管理 UI，内置五类（后端开发/前端开发/测试/DevOps/安全合规）语义就是岗位。**分类升级为岗位，skill.categoryId 机制原样保留**（= 岗位技能库）。

- UI 文案：「技能分类」→「岗位管理」（SkillLibrary.vue 分类管理对话框改名；侧边栏不变，入口仍在 Skill 库页）
- **name 作为业务键**：新增 name 唯一性校验（创建/改名时查重，重复 409）；id 仍内部主键
- 五个内置 seed 分类语义即岗位，不动

### D2：员工 role 引用岗位名，skills / skillCategories 退役

`EmployeeRecord`：

```ts
interface EmployeeRecord {
  id: string;
  name: string;
  role: string;            // 语义变更：必须引用岗位 name（严格校验）
  skills?: string[];       // 退役：保留字段兼容旧数据，调度不再使用；编辑界面移除
  skillCategories?: string[]; // 退役：同上
  capabilities: string[];
  supervision: ...;
  enabled: boolean;
  model?: ...;
}
```

- `validateEmployeeRecord` 新增：role 必须是已存在岗位的 name（400 文案列出可选岗位名）；skills/skillCategories 传了忽略（不报错，兼容旧前端/脚本）
- 调度匹配改为精确岗位：`managed-roster.acquire(role)` → `r.role === role`（替换 `r.skills.includes(role)`）
- 演示数据迁移：现有 demo 员工手工在管理台改档案（数据量 3-4 人，不做自动迁移）；无法匹配岗位的存量员工自然接不到任务，调度器 waiting 日志可见

### D3：注入按岗位（skillsFor 改造）

`server.ts` 装配的 `skillsFor(employeeId)` 改为：

```
员工.role（岗位名）→ 按 name 查分类 → categoryId → skillsForCategories([categoryId])
```

- 员工 `skillCategories` 不再参与注入（纯按岗位）
- 分类被删除但员工 role 引用它：注入返回空清单（不报错），调度匹配自然失败——一致性由「改岗位名走唯一性改名、员工下拉强制选」保证
- fork 快照 / inproc 实时语义不变（`pipeline.ts` 透传链零改动）

### D4：任务发布岗位下拉 = 岗位清单

- TaskCenter 岗位下拉数据源：员工 skills 并集 → `GET /api/skill-categories`（岗位清单）
- yaml 手写 `role:` / 智能生成（task-parser 提示词）语义同步：role = 岗位名；调度匹配不上 = waiting（已有行为，不改）
- `pkg.role` 仍存岗位名字符串（人可读，yaml 友好），不做 id 化

## 测试要点

- name 唯一性：重名 409；改名撞名 409
- 员工校验：role 非岗位名 400（文案含清单）；旧字段忽略不报错
- 调度：岗位精确匹配（含旧 skills 匹配行为移除的用例替换）；点名 assignee 路径不受影响
- 注入：按岗位取 skill；岗位被删注入空清单不炸
- 前端：员工编辑岗位下拉链路、任务创建岗位下拉数据源、技能库分类文案
- 存量兼容：旧 employees.json（含 skills/skillCategories）读入不炸

## 明确不做（YAGNI）

- 岗位独立实体/岗位与分类解耦（复用分类已满足）
- 存量员工自动迁移脚本（演示数据手工改）
- 员工多岗位（单选）
- 一人多岗位注入叠加
