# P16 · 试点汇报材料包（一键 demo + 演示剧本 + 方案一页纸）

> 日期：2026-09-05 ｜ 前置：P0–P15 收官，交付链预演通过
> 定位：试点立项的"可见性"工程。技术已闭环（306 用例/全链路 e2e/交付预演通过），下一步是把项目**讲清楚、演出来**——给领导/评审会一套拿来即用的汇报材料。

## 语义定稿

1. **一键 demo 脚本 `scripts/demo.mjs`**：汇报现场一条命令起全套——
   - 预置演示场景：班组任务包（backend + frontend 两员工依赖编排）+ shadow 盯梢员工（节点申报阻塞 → 现场放行）
   - 起 console-api（`--import ts-register`，端口 3100）+ 控制台前端（vite dev，端口 5173）
   - 打印演示步骤清单与访问地址；`--mock` 用 faux 模型（汇报现场不依赖集群网络稳定性，备用通道）
   - **执行需授权**（监听端口）；脚本正确性由 `--check`/测试保证
2. **演示剧本 `docs/演示剧本.md`**：8–10 分钟汇报流分镜——痛点开场（30s）→ 架构一页（30s）→ 现场演示分镜（任务固化→自动分派→直播看员工干活→shadow 申报→人工放行→审计链校验，5–6min）→ 数据佐证（306 用例/交付预演/离线包，1min）→ 试点诉求（资源清单，1min）；每分镜给操作路径 + 话术要点 + 备选（集群不可达时切 --mock）。
3. **试点方案一页纸 `docs/试点方案一页纸.md`**：领导视角单页——解决什么问题（人效/质量/留痕）、怎么做（数字员工=正式员工身份+盯梢放权渐进）、安全底线五条（模型不出域/凭据加密/双防线沙箱/审计 hash 链/白名单）、试点范围与成功标准、资源诉求清单。
4. **演示数据固定**：`examples/demo-task-package.yaml`（演示任务包：标题/验收标准写成"给领导看的话"）+ demo 用 runtime 样例（含 shadow 级员工）。
5. **边界**：不做 PPT 生成（剧本给结构，PPT 人来做）；demo 脚本不起服务由 agent 自行执行（授权后由人跑）；不改变任何运行时行为。
