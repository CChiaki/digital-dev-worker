# 任务重跑清空工作区 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 同一任务从零重跑时自动清空该任务的 workspace 目录与 session 残留；断点续跑（resume 单节点）保留一切。

**Architecture:** 续跑信号即现成的 `progress?: PlanProgress[]`（scheduler 仅在 `rec.planProgress` 在场时传递，即 resumePlan 语义；重新提交的任务该字段必缺省）。清理点放在执行器入口（inproc `createEmployeeExecutor` + fork `runJob` 两处，语义一致）：`progress` 缺省 → 先 `rm -rf` 任务 workspace、再按 taskId 删除 session（`EmployeeSessionStore.remove` 新增，走 `JsonlSessionRepo.delete` 官方 API），然后照旧 mkdir。`plan-runner` 与 `assembleDefaultRuntime` 不动——它们只构造 store 不打开 session，无残留语义。

**Tech Stack:** TypeScript、node:fs/promises（rm recursive force）、pi-agent-core `JsonlSessionRepo`、vitest。

## Global Constraints

- `progress`（`PlanProgress[]`）在场 = 断点续跑：**一切残留保留**——`resumeWith` 依赖同会话上下文延续与既有产物（2026-09-05 实战语义），清了就断链。
- `progress` 缺省 = 从零执行：清两项——① `workspace/{employeeId}/{taskId}/` 整目录；② 该任务（`{sessionsRoot}/{employeeId}` root 下 cwd=`{root}/tasks/{taskId}`）的 session。
- 清理幂等：目录不存在 / 无 session 均 no-op，不抛错。
- fork 链路（worker.ts）与 inproc 链路（executor.ts）语义必须一致。
- session 删除用 `JsonlSessionRepo.delete(metadata)` 官方 API（`@earendil-works/pi-agent-core@0.84.4`），不自创文件名编码规则（cwd 匹配逻辑复用 `open()` 同款）。
- 测试用中文描述 + 实战日期标注（跟随现有用例风格，如 `（2026-09-06 任务重跑清空）`）。
- 提交规范：中文 conventional commit + `Co-Authored-By: Claude Code <noreply@anthropic.com>`。

```ts
  /** 删除该任务的 session（任务从零重跑时清残留，避免续上旧上下文）。幂等：无 session 时 no-op。 */
  async remove(taskId: string): Promise<void> {
    const taskDir = join(this.root, 'tasks', taskId);
    const existing = (await this.repo.list()).find(
      (m) => (m as { cwd?: string }).cwd === taskDir,
    );
    if (existing) await this.repo.delete(existing);
  }
```
