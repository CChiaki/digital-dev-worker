# P4 · 工作区 + 编码工具集 + browser-mcp 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 数字员工从"只会调 GitLab API"升级为"真正在代码工作区里干活"：独立工作区（容器接口 + 本地实现）、内置编码工具集（read/write/edit/list/grep，路径逃逸防护）、受控 bash（白名单+黑名单+超时+工作区限定）、browser-mcp（Playwright 垫片，transport 可替换）。端到端：在工作区里 改代码 → bash 自测 → git 提交。

**Architecture:**
- **Workspace 接口**（`@ddw/runtime`）：`root`、`resolvePath`（逃逸防护）、`readFile/writeFile/editFile（oldText 唯一命中替换）/listTree/grep`、`exec(cmd)`（受控）。`LocalWorkspace` 本地目录实现；容器（Docker exec 形态）留生产，接口不变。
- **编码工具**：包装为 Tool 注册进 ToolRegistry，与 P2 的 gitlab_/jira_ 工具并列。edit 复用 P0 结论：oldText 唯一命中否则报错回灌模型自纠偏。
- **受控 bash**（`ControlledBash`）：命令白名单（git/npm/node/ls/cat/echo/mkdir/mvn/gradle…）+ BashBlacklist 复用（rm -rf/关机/公网）+ 单次超时 + cwd 恒为 workspace.root + 环境变量收窄。
- **browser-mcp**（`@ddw/mcp-browser`）：`BrowserDriver` 接口（navigate/click/fill/screenshot/getText/close）+ PlaywrightDriver 生产实现（peerDependency，内网装好 playwright 即用）+ 测试用 FakeDriver。工具：browser_navigate/click/fill/screenshot/get_text。
- git 操作测试用真实 git（本机离线可用），仓库为临时目录 `git init`。

**Tech Stack:** TypeScript / vitest / node:child_process（execFile）。不引新运行时依赖。

## Global Constraints

- 沿用 P1-P3 全部约束（离线 / ESM / TDD / Tool 契约 / 不监听端口）
- bash 工具测试只用离线安全命令（echo/ls/git init 等），黑名单用例不真执行
- PlaywrightDriver 不在测试中真正启动浏览器；契约测试全部走 FakeDriver

### 实现校准点（对计划的偏离/发现）

1. **绝对路径语义**：`path.resolve(root, '/x')` 中绝对输入会整体替换 base → 工作区策略定为"绝对路径一律拒绝"，语义更安全更简单。
2. **链式命令禁止**：`&& ; | `` ` `` $()` 一律拒绝（要求分步执行）——白名单只校验首 token，放行链式会绕过校验；e2e 中 git add/commit 分步调用验证此设计可用。
3. **引号感知分词**：`shell:false` 下自写 tokenizer（支持单双引号）替代 naive split，git commit 中文含空格消息用例通过。
4. **非零退出语义**：命令运行但退出码非 0 时返回 `ok:false` **并附 stdout/stderr**——模型需要失败输出定位问题（如 node test 报错信息）。
5. **工具层统一兜底**：`tool()` helper 内 try/catch 把 Workspace/driver 抛错统一转 `ok:false`，保证 ToolResult 契约（P2 `fail()` 教训的应用）。
