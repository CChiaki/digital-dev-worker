# 存储企业化改造 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** runtime yaml 新增 `storage:` 段（driver: sqlite|mysql），7 个存储域全部落库——sqlite/mysql 双驱动一次交付，JSON 文件形态从部署运行时消灭。

**Architecture:** 自研 `SqlDriver` 薄抽象（`stores/sql/`），node:sqlite 与 mysql2 两实现；7 个 store 基于驱动实现（接口不变，业务代码零改动），装配按 driver 分支一次。窄列 + doc JSON 列建表（`ddw_` 前缀 8 表）。

**Tech Stack:** node:sqlite / mysql2 ^3 / yaml / vitest

**Spec:** `docs/superpowers/specs/2026-09-09-存储企业化-design.md`（表结构/方言决策/迁移/安全详见 spec，本计划不重复）

## Global Constraints

- 存储接口（`stores/types.ts` 的 TaskStore/EventStore + 各档案 store 方法面）**签名零变化**，业务代码（handlers/scheduler/executor/distiller）不得改动。
- File* store 类全部保留（migrate 读取旧数据 + 测试对照），仅装配层退役：`--store` CLI 参数传入即报错退出；server.ts 装配只有 driver 分支。
- mysql 凭据支持 `enc:v1:`（resolveSecret）与明文；**任何真实凭据不入 git**——测试 mysql 连接只经 `DDW_TEST_MYSQL_URL` env，缺 env 时 mysql 测试分支全部 skip（离线 CI 全绿）。
- 缺省行为零回归：无 storage 段 = sqlite + `<dataDir>/ddw.sqlite`。
- storage 段来自 runtime yaml（`--runtime`）；无 runtime yaml 时一律缺省 sqlite。
- hash 链语义不变：同 id 重放忽略不炸、verifyIntegrity 全链重算、snapshotHead 仍写库外文件。
- 全程简体中文注释/报错；conventional commits 中文；不启动服务/容器（测试用连接不占常驻端口；本机 MySQL 已由用户提供，测试库 `ddw_test` 由 T4 自动建库建表，跑完即弃数据）。

```ts
// driver.ts
export interface SqlDriver {
  ensureSchema(): Promise<void>;                       // 幂等建 8 表 + 索引
  exec(sql: string, params?: unknown[]): Promise<void>; // DDL/无返回
  run(sql: string, params?: unknown[]): Promise<{ affected: number }>; // DML，affected=changes/affectedRows
  all<T = unknown>(sql: string, params?: unknown[]): Promise<T[]>;
  tx<T>(fn: () => Promise<T>): Promise<T>;             // BEGIN/COMMIT/ROLLBACK
  upsertSql(table: string, pkCol: string, cols: string[]): string; // 方言 upsert
  encodeJson(v: unknown): unknown;                     // 统一 JSON.stringify 字符串入库
  decodeJson<T>(v: unknown): T;                        // string→parse，非 string 原样（防御 mysql2 行为差异）
  close(): Promise<void>;
}
export const TABLES = ['ddw_tasks','ddw_events','ddw_employees','ddw_skill_categories','ddw_skills','ddw_capabilities','ddw_messages','ddw_channels'] as const;
```

- [ ] **Step 1: schema.ts**——`DDL: { sqlite: string[]; mysql: string[] }` 两份字面量 DDL（T1 先含全部 8 表，档案表列按 spec §5；mysql 用 `BIGINT AUTO_INCREMENT`/`JSON`，sqlite 用 `INTEGER PRIMARY KEY AUTOINCREMENT`/`TEXT`）。8 表列规格：

```sql
-- ddw_tasks: id TEXT/VARCHAR(64) PK, status TEXT NOT NULL, claimed_by TEXT NULL, claimed_at BIGINT NULL,
--            pkg JSON NOT NULL, result JSON NULL, plan_progress JSON NULL, failed_item_id TEXT NULL, updated_at BIGINT NOT NULL
--            索引: status
-- ddw_events: seq 自增 PK, id TEXT NOT NULL UNIQUE, ts BIGINT NOT NULL, task_id TEXT NOT NULL, employee_id TEXT NOT NULL,
--            type TEXT NOT NULL, summary TEXT NOT NULL, payload JSON NULL, prev_hash TEXT NULL, hash TEXT NULL, hash_version INTEGER NOT NULL DEFAULT 1
--            索引: task_id, employee_id, type, ts
-- ddw_employees: id TEXT/VARCHAR(64) PK, enabled INTEGER NOT NULL DEFAULT 1, doc JSON NOT NULL, updated_at BIGINT NOT NULL
-- ddw_skill_categories: id TEXT PK, name TEXT NOT NULL UNIQUE, doc JSON NOT NULL
-- ddw_skills: id TEXT PK, category_id TEXT NOT NULL, status TEXT NOT NULL, doc JSON NOT NULL   -- 索引: category_id, status
-- ddw_capabilities: kind TEXT PK, doc JSON NOT NULL
-- ddw_messages: id TEXT PK, read INTEGER NOT NULL DEFAULT 0, created_at BIGINT NOT NULL, doc JSON NOT NULL  -- 索引: read
-- ddw_channels: id TEXT PK, doc JSON NOT NULL
```

（doc JSON 列：mysql `JSON`；payload/doc 等所有 JSON 列统一走 encodeJson=JSON.stringify 字符串 + TEXT/JSON 列均可存字符串。）

- [ ] **Step 3: 跑测试确认失败 → SqliteDriver 实现 → 通过**。tx 实现：`exec('BEGIN'); try { const r = await fn(); await exec('COMMIT'); return r; } catch (e) { await exec('ROLLBACK'); throw e; }`。upsertSql（sqlite 方言）：

```ts
upsertSql(table, pkCol, cols) {
  const all = [pkCol, ...cols];
  const updates = cols.map((c) => `${c} = excluded.${c}`).join(', ');
  return `INSERT INTO ${table} (${all.join(', ')}) VALUES (${all.map(() => '?').join(', ')}) ON CONFLICT(${pkCol}) DO UPDATE SET ${updates}`;
}
```

```ts
const updates = cols.map((c) => `${c} = VALUES(${c})`).join(', ');
```
