## 目标

把系统从「开发机可跑」推进到「试点机可交付」：交付包拿到内网试点机上，
按文档完成离线安装 → 配置凭据（密文落盘）→ `doctor` 巡检全绿 → 启动即用。

## 语义定稿（用户方向已拍板：试点交付准备）

- **凭据加密**：spec 4.7/7.3「凭据托管 MCP 凭据库，一期加密配置」。定稿：
  - 算法 AES-256-GCM（node:crypto 内置，零依赖零编译，契合离线原则）
  - 密文格式 `enc:v1:<iv_b64>:<ct_b64>:<tag_b64>`（版本化，未来换算法/加字段不断配置）
  - 主密钥来自环境变量 `DDW_CRED_KEY`（base64 的 32 字节密钥；试点机由运维生成一次、注入 systemd/启动环境，**不落盘**）
  - runtime yaml 的 `apiKey` 明文/密文**两用**：`enc:v1:` 前缀即解密，否则按明文（P9 零回归）
  - 解密失败（缺 env / 错 key / 篡改密文）= 启动即失败、错误信息可读（宁可不起，不带病运行）
  - CLI 子命令 `cred key`（生成主密钥）、`cred enc <明文>`（产出密文，粘贴进 yaml）
- **巡检 CLI（doctor）**：交付/巡检一条命令体检，检查项每项输出 ✓/✗ + 明细，任一失败退出码 1：
  1. Node ≥ 20.5（node:sqlite 可用）
  2. 数据目录可写
  3. 存储打开 + 审计 hash 链 integrity 校验（已有数据是否被篡改）
  4. runtime yaml 解析 + 凭据解密（提供 --runtime 时）
  5. bash 白名单命令在 PATH 中存在（which）
  6. 模型集群连通探测（仅 `--probe`，内网不通时给出可读原因，不阻塞其余项）
  - 实现纯注入化（检查函数接受 deps，测试不监听端口、不依赖真实集群）
- **离线安装包**：`scripts/offline-pack.mjs` 在**有网开发机**产出离线包（pnpm store + 仓库源码 tar）；
  `scripts/offline-install.sh` 在**试点机**解包 → `pnpm install --offline` → `pnpm -r test` 冒烟。
  本环境只写脚本不执行打包（遵守不擅自打包约定）。

## Task 分解

### T1 凭据加密（credentials + runtime-config 集成 + CLI 子命令）
- Create: `packages/console-api/src/team/credentials.ts`
  - `generateMasterKey(): string`（randomBytes(32) → base64）
  - `encryptSecret(plain, masterKey): string`（iv 随机 12B；格式 `enc:v1:iv:ct:tag`）
  - `decryptSecret(enc, masterKey): string`（非 enc:v1: 前缀原样返回？——**否**，decryption 只管密文；明文两用逻辑在 resolveCredentials）
  - `resolveSecrets(config, env)`：遍历 routes，`enc:v1:` 前缀 → 解密替换；缺 `DDW_CRED_KEY` / key 无效 / GCM auth 失败 → 可读错误（`凭据解密失败：…`）
- Modify: `runtime-config.ts` 的 `loadRuntimeConfig(path, env?)` 与 `parseRuntimeConfig`（可选 resolve 步骤，默认用 process.env）
- Modify: `cli.ts`：子命令 `cred key` / `cred enc <明文>`（输出后退出，不起服务）；--runtime 路径接入 resolveSecrets
- Test: `packages/console-api/test/credentials.test.ts`（≥6 用例：roundtrip、明文透传零回归、缺 env 可读报错、错 key 报错、篡改密文 auth 失败、parseRuntimeConfig 集成密文）

### T2 巡检 CLI（doctor）
- Create: `packages/console-api/src/doctor.ts`
  - `runChecks(deps): CheckResult[]`（deps 注入：dataDir、runtimePath、env、execFile for which、probe fetch）
  - `formatChecks(results): string`（对齐的 ✓/✗ 报告）
- Modify: `cli.ts`：子命令 `doctor [--data …] [--runtime …] [--probe]` → 报告 + 退出码
- Test: `packages/console-api/test/doctor.test.ts`（≥5 用例：全绿路径、坏 yaml、缺凭据 env、白名单命令缺失、报告格式与退出码）

### T3 离线安装包（脚本 + 文档，不执行）
- Create: `scripts/offline-pack.mjs`（开发机：pnpm store pack + 源码 tar，产出 `dist-offline/`）
- Create: `scripts/offline-install.sh`（试点机：解包 → `pnpm install --offline --frozen-lockfile` → `pnpm -r test` 冒烟 → 提示 doctor）
- Modify: `README.md` 增「试点机离线交付」章节（两脚本用法 + 凭据生成/注入流程 + doctor 巡检）

## 验收标准

1. `apiKey` 密文/明文两用；密文路径全程零回归（明文配置行为不变）
2. 凭据异常（缺 DDW_CRED_KEY / 错 key / 篡改）启动即失败且错误可读
3. `cred key` / `cred enc` 可完成"生成密钥→加密→yaml 落盘→启动解密"闭环
4. `doctor` 一键巡检：检查项可读、失败退出码 1、测试不依赖端口/真实集群
5. 离线安装脚本 + 文档就绪（打包动作待用户指令或交付时执行）；全仓回归全绿

## 边界（试点期不做）

- systemd / 开机自启配置（试点机由运维模板下发）
- 凭据轮换策略（人工换 key 重加密即可）
- 多套环境（test/staging）差异化配置文件管理
