# P5 · CI/部署/验证环境 MCP + 执行层沙箱化 + 直播/审计升级 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 收官阶段——补齐任务全链路的最后三环（构建→部署→环境验证），落实 spec 4.7 执行层双实现（SandboxBackend），控制台直播升级 SSE、审计台账 v2，最终全链路闭环演示：**接单→编码→自测→MR→Jira→构建→部署→环境验证→汇报**。

**Architecture:**
- **SandboxBackend**（spec 4.7 兑现）：中间层接口，三实现 Noop/Bwrap/Docker——只是"把原命令翻译成沙箱内 argv"，ControlledBash 注入使用，软防线原样复用。
- **@ddw/mcp-ci**：`CiTransport` 注入 + 4 工具（触发构建/查状态/等待结果/查日志尾部）。
- **@ddw/mcp-deploy + @ddw/mcp-testenv**：同构 transport 注入模式；deploy（部署到环境+查部署记录）、testenv（探活+健康详情）。
- **console-api 升级**：SSE 直播（`GET /api/events/stream`，`res` 对象注入式实现，测试不监听端口）+ 审计 v2（任务级聚合视图：状态+时间线+工具统计）。
- **e2e**：全链路闭环（全 fake transport + Faux，同进程）。

**Tech Stack:** TypeScript / vitest；全部离线，测试不监听端口。

## Global Constraints

- 沿用 P1–P4 全部约束（离线 / ESM / TDD / Tool 契约 / transport 注入）
- BwrapBackend/DockerBackend 只生成 argv，测试不真执行沙箱/容器
- SSE 实现为"向注入的 res 写 SSE 帧"，测试用 mock res

### Task 1: SandboxBackend 中间层（spec 4.7 落地）

**Files:**
- Create: `packages/runtime/src/workspace/sandbox.ts`
- Test: `packages/runtime/test/sandbox.test.ts`

**Interfaces:**
- `interface SandboxBackend { wrap(cmd: string[]): string[]（包装 argv）; readonly name: string }`
- `NoopBackend`：原样返回
- `BwrapBackend(opts: { workspace: string; net?: boolean（默认 false 断网）; tmpfs?: string[] })`：生成 `bwrap --ro-bind /usr /usr --proc /proc --dev /dev --bind <ws> /workspace --tmpfs /tmp [--unshare-net] --unshare-pid -- <原argv>`
- `DockerBackend(opts: { container: string; workdir?: string })`：生成 `docker exec --workdir <dir> <container> <原argv>`
- `ControlledBash` 增加 `backend?: SandboxBackend` 注入：exec 时 argv 先过 backend.wrap 再 execFile（bin=argv[0] 白名单校验仍针对**原始命令**的首 token）
- [ ] 失败测试（三实现 argv 快照断言 + ControlledBash 注入后真实执行仍走 Noop 白名单逻辑）→ 实现 → 回归 → 提交

### 实现校准点

1. **e2e 落位**：计划写 `packages/runtime/test/e2e-full-chain.test.ts`，实际落 `packages/console-api/test/`——SSE handler 与审计 v2 聚合路由都在 console-api 包，跨包引用会形成 runtime→console-api 反向依赖；console-api 已有 runtime/mcp-* 的 test devDeps 先例。
2. **SSE since 语义**：沿用 EventStore 的 `ts >= since`（at-least-once，客户端按 id 幂等去重），比严格大于更安全（不丢同毫秒事件）；handler 内以已推 id 集合防无限重推（这是首次测试运行暴露的真实 bug）。
3. **SandboxBackend 定位**：只做"原始 argv → 沙箱内 argv"翻译，不做执行；Bwrap/Docker 在测试中仅断言 argv，不真执行（内网试点机装 bubblewrap 后即插即用）。
