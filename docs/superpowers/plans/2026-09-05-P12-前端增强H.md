日期：2026-09-05 ｜ 状态：进行中
前置：P11 试点交付准备已收官（263 用例全绿）。

## 目标

控制台前端从「能用」到「好用」：班组编排从文字徽章升级为**依赖分层图**，
任务详情接入**审计 v2 聚合**（工具调用统计）与**节点验收四态**（待申报/待放行/已放行/已驳回），
对齐 shadow 盯梢的操作员视角。**零新增 npm 依赖**（内网离线原则）。

## 语义定稿

- **编排视图**：任务池顶部「列表 / 编排」切换。编排 = DAG **拓扑分层列**：
  - `level(t) = deps 为空 ? 0 : max(level(dep)) + 1`；缺失/失败依赖的任务仍进 max+1 层（blocked 可见，不隐藏）
  - 同层按 taskId 稳定排序；卡片显示状态徽章 + 岗位 + 依赖名；列头「第 N 层」
  - 不画 SVG 连线（层列布局已表达流向，卡片内列依赖 id 供溯源，实现最简）
- **节点验收四态**（TaskDetail 清单行，数据 = task_check 事件 ∪ intervention 事件，按项归组取最新）：
  | 状态 | 判定 |
  |---|---|
  | 待申报 | 无 task_check |
  | 待放行 | 最新 task_check 带 `awaiting: true` 且其后无 intervention |
  | 已放行 | 最新 intervention `approved: true` |
  | 已驳回 | 最新 intervention `approved: false`（行内显示驳回意见，员工正在修正） |
  - 申报摘要（result）始终展示
- **审计 v2 接入**：TaskDetail 新增「执行档案」卡片：`GET /api/audit/:taskId` 的 toolCalls 统计（名称×次数×错误）+ 最终回复
- **实时感**：TaskDetail 5s 轮询（对齐名册/放行页惯例），onBeforeUnmount 清理
