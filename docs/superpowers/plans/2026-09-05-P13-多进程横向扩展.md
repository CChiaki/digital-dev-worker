# P13 · 前置环节 C：多进程横向扩展（执行隔离 + 多实例调度安全）

日期：2026-09-05 ｜ 状态：进行中
前置：P12 前端增强已收官（272 用例全绿）。

## 目标

规模化地基：**员工执行 fork 到独立子进程**（崩溃隔离——员工进程崩不拖死控制台；
CPU/IO 密集执行不影响 API 响应），事件经 IPC 回主进程统一落库（hash 链保序不变）；
shadow 人工放行闸门跨进程闭环；**多实例调度安全**用例证明（claim 原子抢单兜底）。
`--exec-mode inproc|fork` 默认 inproc 零回归。

## 语义定稿

- **进程模型**：每任务一个 worker（fork，跑完即退）——试点期单机、任务数小，进程即隔离单元；
  常驻进程池留二期（spec 4.1"每员工常驻 Agent 进程"为概念模型，D2 已定单进程多 runtime）。
- **事件流向**：worker 内建 EventBus → IPC `send({type:'event', event})` → 主进程统一 append。
  hash 链序 = 主进程到达序，单 worker 单任务内有序；worker 不直接写 store（杜绝跨进程并发写）。
- **闸门跨进程**：worker task_check 阻塞 → IPC `{type:'gate-wait', check}` → 主进程
  `reviewQueue.wait()` → verdict IPC 回传 → worker 继续或按驳回修正。P10 语义不变，
  待审列表仍由主进程事件流推导（重启安全不变）。
- **失败语义**：worker 非零退出 / IPC 断连 → outcome `{status:'max_turns', reply:'执行进程异常退出: …', turns:0}`
  → scheduler `ok=false` → 任务 failed、下游 blocked（与 P8 失败传播保守取向一致）。
- **worker 组装复用**：从 `createEmployeeExecutor` 抽出 `assembleDefaultRuntime(opts, task, employee)`
  ——in-process 与 worker 共用同一组装（gateway/tools/supervision/gate 判断一处实现）。
- **多实例**：控制台 API 进程无状态可多开（读侧扩容零改动）；调度建议单 leader 实例，
  双实例并存时 `tasks.claim` 原子抢单保证不重复分派（P8 已有机制，P13 用双实例用例证明）。

## 验收标准

1. fork 模式一条链 e2e 走通：固化 → 分派 → 独立进程执行 → 事件落主库 → integrity ok
2. shadow 闸门跨进程闭环：待审可见 → 驳回意见回传 worker → 修正重报 → 放行 → done
3. worker 崩溃不拖死控制台：任务 failed、下游 blocked、进程可继续接新任务
4. 双调度实例并发 tick 不重复分派（claim 原子兜底）
5. inproc 默认零回归（272 用例全数保留）；全仓回归全绿 + typecheck 干净

## 边界（试点期不做）

- 常驻进程池 / worker 复用（每任务 fork 即退，进程创建成本试点期可接受）
- 跨机分布式调度（单机多进程即可；跨机 = 存储层换 MySQL 后另议）
- worker 内 checkGate 之外的远端协作工具（MCP transport 注入形态不变，随任务配置走）
- 任务级执行超时强制杀死（试点期人在旁边；崩溃语义已覆盖进程挂死主路径）
