# P2 · 任务包数据模型 + GitLab/Jira MCP 工具 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 数字员工"接单干活"的数据与工具侧打通：任务包 yaml → 任务简报（systemPrompt）接入 EmployeeRuntime；GitLab 工具集（建分支/提交文件/建 MR/查 MR）与 Jira 工具集（查单/改状态/评论）注册为 runtime Tool——API 适配器形态（MCP 契约），行内不可达时全部经注入的 fake HTTP 可测。

**Architecture:** 三个包：
- `@ddw/runtime` 扩展：`TaskPackage` 类型 + yaml 解析校验 + `buildTaskBrief`（任务包→systemPrompt），EmployeeRuntime 接线
- `@ddw/mcp-gitlab`：GitLab REST 工具集（实现 runtime 的 `Tool` 接口），HTTP 经注入的 `GitLabTransport`（生产=fetch，测试=fake）
- `@ddw/mcp-jira`：Jira REST 工具集，同构

**契约先行**（spec 第 7 节）：工具契约（名称/参数/返回）保持稳定，背后是 API 适配器还是 Playwright UI 垫片可切换——本阶段全部 API 适配器；无 MCP Server 进程，工具直接进程内注册（P0 结论：pi 工具即 AgentTool，无需额外 MCP 运行时；"MCP"此处指工具契约规范）。

**Tech Stack:** TypeScript 5.5+ / vitest；新增运行时依赖仅 `yaml`（任务包解析）。HTTP 用全局 fetch（Node 20+），零 SDK 依赖。

## Global Constraints

- 沿用 P1 全部约束（离线测试 / ESM / TDD / Tool 契约 / AgentEvent 留痕）
- 行内 GitLab/Jira 地址、token 全部来自配置注入，禁止硬编码；测试不发真实请求
- 工具失败统一走 `ToolResult { ok:false, error }` → toPiTool 抛异常 → isError 回灌模型（P1 已验证链路）
- 每个工具的写操作（建分支/提交/MR/改状态）都经由 runtime 事件流自动留痕，无需额外埋点

### Task 3: GitLab 工具集（`@ddw/mcp-gitlab`）

**Files:**
- Create: `packages/mcp-gitlab/package.json` / `tsconfig.json`
- Create: `packages/mcp-gitlab/src/transport.ts`（`interface GitLabTransport { request(method, path, body?): Promise<{ status: number; json: unknown } }`；`class FetchGitLabTransport`；生产 token/baseUrl 注入）
- Create: `packages/mcp-gitlab/src/tools.ts`（5 个 Tool + `createGitLabTools(deps): Tool[]`）
- Test: `packages/mcp-gitlab/test/tools.test.ts`（fake transport 记录请求/返回预置响应）

**工具契约**（名称稳定，后续 Playwright 垫片同契约替换）：

| 工具 | 参数 | 行为 | GitLab API |
|---|---|---|---|
| `gitlab_create_branch` | repo, branch, from | 幂等：已存在视为成功 | POST /repository/branches |
| `gitlab_commit_files` | repo, branch, files[{path, content}], message | 逐文件 commit（jobs API 或 tree+commit，v1 用单 commit 多 action） | POST /repository/commits |
| `gitlab_create_mr` | repo, source, target, title, description | 返回 mr iid/url；已存在同源同目标 MR 返回已有（幂等） | POST /merge_requests |
| `gitlab_get_mr` | repo, mr_iid | 返回 state/合并状态/web_url | GET /merge_requests/:iid |
| `gitlab_get_file` | repo, branch, path | 返回文件内容（base64 解码） | GET /repository/files/:path |

**Interfaces:**
- `interface GitLabDeps { transport: GitLabTransport; defaultRepo?: string }`
- 测试用例：建分支请求体正确；commit_files 组包 multi_action；create_mr 幂等（transport 先返回 409/已存在再查）；非 2xx → `{ok:false, error:'GitLab 405: <body>'}`；get_file base64 解码
- [ ] 失败测试 → 实现 → 回归 → 提交 `feat(mcp-gitlab): GitLab 工具集(建分支/提交/建MR/查MR/读文件)`
