# P10 · 人工盯梢闭环（2026-09-05）

**Goal**：项目立项目的最后一块开发侧拼图——「等同正式员工，**前期有人盯梢**」落地为可验证闭环：数字员工在关键节点调用 `task_check` 申报后，**shadow 级别下暂停等待人工放行**；人通过控制台通过（员工继续）或驳回（员工收到意见继续修正后重新申报）。一条链走到底：申报阻塞 → 待审队列 → 人工放行/驳回 → 继续执行 → 审计留痕。

## 语义定稿

- **shadow**：每个 task_check 节点阻塞等待人工放行（试点盯梢期默认）
- **assisted / trusted**：不阻塞，照旧只留痕（人工可随时 steer/看直播）
- 驳回 = 工具返回 `{ ok: false, error: '人工驳回: <意见>' }`——模型看到工具错误自然修正，修正后重新申报（task_check 不限制重复申报）；每次放行/驳回 emit `intervention` 事件留痕
- 放行/驳回请求与待审员工**不强绑定任务执行者**（盯梢人视角按任务审）

## P10 验收标准

1. `pnpm -r test` 全绿 + typecheck 干净、全离线；P9 及之前行为零回归（无 gate 时 task_check 照旧）
2. shadow 级别：task_check 阻塞 → 控制台可见待审 → 放行后执行继续；驳回后员工收意见修正并重新申报
3. 放行/驳回 intervention 事件留痕，审计可溯；待审列表事件流推导，重启安全
4. 人工放行阻塞不拖死调度器（其他任务照常分派）
5. e2e-supervision 一条链一次跑通（驳回修正场景在内）

## 边界（试点期不做）

- assisted 级别抽查放行（概率放行）
- 移动端/消息推送通知盯梢人
