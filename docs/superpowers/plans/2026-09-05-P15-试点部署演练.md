# P15 · 试点部署演练（交付预演闭环）

> 日期：2026-09-05 ｜ 前置：P0–P14 全部收官（299 用例）
> 定位：spec「落地路径」一期收官动作。P11 备齐了交付零件（offline-pack / install.sh / doctor），但**从未整体走过一遍**——交付当天现场踩坑是当前最大风险。P15 把"交付动作"本身变成可重复、可验证的演练闭环。

## 语义定稿

1. **演练脚本 `scripts/rehearsal.mjs`**：开发机一键预演 = 打包（可 `--skip-pack` 复用已有包）→ 解包到临时目录（模拟试点机）→ 执行 `install.sh`（离线安装 + 冒烟）→ `doctor`（不带 `--probe`，不出网）→ 输出逐项报告，任一失败退出码 1。**执行需用户/运维授权**（涉及打包与安装命令）；脚本正确性由测试保证。
2. **install.sh 加固**：① Node 版本前置检查（< 20.5 首错即拦，可读报错）；② 冒烟失败给出排查提示（store 路径 / 锁文件 / 磁盘）；③ 步骤带耗时输出。试点机首错即拦比装到一半失败便宜得多。
3. **offline-pack 加固**：打包完成后校验产物（`tar -tzf` 抽查 repo/ pnpm-store/ install.sh / OFFLINE.md 齐全）+ 打印体积——包损坏在开发机发现，不上试点机。
4. **systemd 部署单元**：`scripts/ddw-console.service` 样例（Environment 注入主密钥、ExecStart 走 cli.ts、Restart 策略、数据目录）——试点机"怎么常驻"有标准答案。
5. **试点部署手册 `docs/试点部署手册.md`**（runbook）：交付物清单 → 前置条件 → 安装 → 凭据配置 → 巡检 → systemd 启动 → 冒烟验收清单（固化任务包→执行→直播可见→审计链校验）→ 故障排查表（doctor 每个可能的 ✗ 对应处理）→ 回滚（数据目录备份/恢复）。
6. **测试防回归**：`delivery-rehearsal.test.ts`——脚本语法检查（`bash -n` / `node --check`）+ 关键行为断言（install.sh 含 `--offline --frozen-lockfile --store-dir`、Node 前置检查存在；rehearsal 串联步骤齐全；service 文件含主密钥注入）。**测试不执行打包/安装**（那是要授权的重动作）。
7. **沿用既有约定**：演练全程不监听端口（doctor 不带 probe、冒烟是 pnpm -r test）；启动/打包命令只写进文档与脚本，不由 agent 擅自执行。

## 边界（本轮不做）

- 不真的执行打包与演练（需授权，交付时由人跑 `node scripts/rehearsal.mjs`）
- 不做 MySQL/集群生产化、不做前端构建产物打包（console 前端 dev 模式试点够用）
- 不引入新依赖；systemd 单元是样例非自动安装
