# 数字AI研发人员

**面向企业内网的 AI 数字员工研发平台 —— 让 AI 像一名真正的员工一样，接入研发工具链，从接单到交付，可管控、可审计、可沉淀。**

> 产品文档 ｜ 2026-09 ｜ 试点就绪（全链路已真实跑通，等企业内资源接入）

---

## 一、行业背景：AI 正在重写软件研发，但企业侧"用不起来"

AI 编码能力近两年出现台阶式跃升：从代码补全进化到能自主理解需求、编写完整功能、修复缺陷、执行测试的 **AI Agent（智能体）**。业界头部实践已经验证——AI 不再是"辅助打字的工具"，而是可以承担完整研发任务环节的"数字劳动力"。

但当企业（尤其是金融、政企等强合规行业）真正想把 AI Agent 用起来时，几乎都卡在同样的三道墙：

1. **数据出不了内网**——云端 SaaS 编码助手要求代码、需求、日志上传第三方，金融/政企行业的合规底线直接把这条路封死；
2. **AI 接不进企业内工具链**——GitLab、Jira、CI/CD、部署平台、测试环境都在内网，通用 AI 助手没有任何通道触达，"能写代码但交不了差"；
3. **不敢放权**——AI 直接操作生产研发流程，没有审批闸门、没有审计留痕、没有权限边界，出了问题无法追责，业务部门与科技部门都不敢签字。

**市场上要么是"个人效率工具"（单机插件、SaaS 助手），要么是"大模型底座"（企业内建模型平台）——缺的恰恰是中间这一层：把大模型能力变成一支可管理、可编排、可审计的"数字员工队伍"的企业级执行平台。这就是本产品的位置。**

## 二、痛点：企业研发组织今天的真实处境

### 痛点 1：人力大量消耗在"低价值但必须在场"的环节上

一条研发链路——需求流转、环境准备、编码、提交评审、触发构建、部署验证、冒烟测试、汇报同步——其中大量环节是规则化、重复性的操作。但每一个环节都要求**人必须在场**：等构建要盯着、部署要守着、验证要手动点。研发工程师的真实有效编码时间被严重稀释，高级人才做的是流水线的事。

### 痛点 2：组织知识只存在个人脑子里，人走了经验就清零

开发规范、项目上下文、踩坑经验、修复方案——散落在个人记忆和零散文档里。同样的坑不同的新人反复踩；质量高度依赖个人水平；新人 ramp-up 周期长。**组织在研发上最大的资产（经验）从未被资产化。**

### 痛点 3：AI 工具"散装使用"，无法形成组织级能力

个人装的插件、个人申请的 API——各自为战、水平参差、无法统一管控。AI 帮了某个人的忙，但对组织的研发效能没有可统计、可管理、可放大的贡献。

### 痛点 4：合规与审计是"一票否决项"

金融/政企行业对"代码由 AI 写的"极度敏感：AI 改了什么、依据什么改的、谁批准的、能否追溯——没有这套机制，任何 AI 落地方案在科技风控那里都过不了会。

### 痛点 5：单人试用容易，"成建制使用"无解

一个团队要真正用 AI 干活，需要的是：任务怎么分派、多人任务怎么编排依赖、产出怎么验收、员工"能力"怎么定义和管控、新员工（数字的）怎么快速继承组织技能——**这层"组织操作系统"没有任何现成产品覆盖。**

## 三、我们的产品：数字员工研发平台

### 3.1 一句话定位

> **在内网离线环境，给每个研发岗位配一名可管控、可审计、能真实干活的"数字员工"，接入企业既有研发工具链，从接单到交付全流程自动化。**

### 3.2 产品形态

- **数字员工**：有档案（姓名/岗位/能力/盯梢等级/专属模型配置）、有工位（独立工作区）、有技能（挂载岗位技能库）、有考勤（全程审计）的 AI 执行体；
- **管理台**：管理者像管理真人团队一样管理数字员工——建档案、分任务、看进度、审节点、管技能、查台账；
- **执企业内核**：企业私有化部署，模型可接企业内 GPU 集群或合规网关，数据全程不出内网。

### 3.3 核心功能全景

| 能力域 | 内容 |
|---|---|
| **任务接单与执行** | 任务创建三模式（表单 / YAML / 智能生成）；任务包声明岗位、计划步骤、验收方式；调度器自动分派或点名指定员工 |
| **真实工具链接入** | MCP 标准化工具矩阵：GitLab/MR、Jira、CI、部署、测试环境、浏览器；无 API 的老系统走 UI 自动化垫片兜底——**数字员工能真实提交代码、建 MR、触发构建、部署验证** |
| **班组协作编排** | 多任务依赖声明（DAG）、并行分派、失败自动阻断下游、断点续跑——支持"一个班组协同交付一个需求"的成建制作业 |
| **盯梢放权三级** | shadow（关键节点阻塞等人工放行）→ assisted（留痕不阻塞）→ trusted（自主执行）——**信任渐进式开放，风险始终有闸门** |
| **能力注册表** | 每类任务可用的工具集声明式绑定（开发/测试/提交/运维四类预设），数字员工拿到的工具严格受控 |
| **岗位即技能库** | 岗位（后端开发/前端开发/测试/DevOps/安全合规…）下挂技能知识库；员工按岗位注入对应知识，精准到"干哪行带哪行的行规" |
| **技能自动沉淀** | 数字员工每完成一个任务，自动蒸馏产出候选技能/开发约束，人工终审后入公共技能库——**组织知识滚雪球式资产化** |
| **全程审计与直播** | 每一步操作事件级直播可回放；审计台账带 hash 链（篡改可检测）；节点验收四态（待申报/待放行/已放行/已驳回） |
| **企业级交付** | 离线打包+安装脚本+巡检 CLI；凭据 AES-256-GCM 密文落盘；通知渠道（钉钉/企微/Webhook） |

## 四、我们能解决的问题：痛点 → 解法 → 结果

### 问题 1：研发人力被重复劳动稀释
**解法**：数字员工承担规则化执行环节——接单、编码、提交 MR、触发 CI、部署、环境验证、汇报，全自动走完；管理者只需在关键节点审批。
**结果**：已在本项目内真实跑通"接单 → 编码 → 提交 MR → 构建 → 部署 → 环境验证 → 汇报"的**全链路闭环**，不是 PPT 演示，是可复现的工程事实（一键演示脚本 + 交付预演均真跑通过）。

### 问题 2：AI 不敢用、放不了权
**解法**：三级盯梢放权 + 节点申报审批闸门。上线初期全部 shadow 级——AI 每到关键节点停下来等人放行；跑熟后逐员工逐任务提升信任等级；每一次放行/驳回都进审计链。
**结果**：**风险控制嵌入执行流本身**，科技风控能看到"AI 在哪一步、做了什么、谁批的"，放权有据、追责有链。

### 问题 3：组织知识不沉淀
**解法**：岗位化技能库 + 任务完成自动蒸馏。数字员工干活时按岗位注入组织沉淀的规范与知识；干完活自动把新经验蒸馏成候选技能，人工终审入库，其他员工下个任务就能用上。
**结果**：**经验从"个人记忆"变成"组织资产"**，且在真实任务流里自动积累——不是靠人写文档。

### 问题 4：云端 AI 进不了内网
**解法**：全栈私有化部署，离线安装交付（安装+巡检+回滚预案齐备）；模型网关双协议适配（OpenAI 兼容 / Anthropic 协议），企业内 GPU 集群或合规模型网关即插即用。
**结果**：**数据、模型、工具链三样全在内网**，合规底线从架构上满足。

### 问题 5：单人试用容易、成建制使用无解
**解法**：班组编排（依赖 DAG + 并行 + 失败阻断）、员工多岗位（一人可兼多岗，按任务精准注入对应技能）、能力注册表（工具权限声明式管控）、管理台（档案/任务/技能/审计一体化）。
**结果**：**从"一个工程师的插件"升级为"一支可管理的数字员工队伍"**——这是本产品与所有个人工具的本质区别。

### 问题 6：老系统没有 API，AI 够不着
**解法**：Playwright UI 自动化垫片适配器——对无 API 的内部老系统（如老旧 Jira），AI 用"像人一样操作界面"的方式完成流转，登录态维护、幂等防重、截图取证齐备。
**结果**：**存量系统不改造就能被 AI 接管**，落地门槛大幅降低。

## 五、差异化与竞争位置

| 维度 | 云端 SaaS 编码助手（Copilot 类） | 企业内自建大模型平台 | **本产品** |
|---|---|---|---|
| 数据合规 | ❌ 代码/需求出内网 | ✅ | ✅ 全栈内网离线 |
| 工具链触达 | ❌ 接不了内网系统 | ❌ 只出模型，不出执行力 | ✅ MCP 工具矩阵 + UI 垫片，真实提交/构建/部署 |
| 组织级管控 | ❌ 个人订阅、散装使用 | — | ✅ 员工档案/能力注册表/盯梢放权/审计 hash 链 |
| 任务编排 | ❌ 单人单点 | — | ✅ 班组 DAG 依赖编排 + 多进程扩展 |
| 知识沉淀 | ❌ 无 | — | ✅ 岗位技能库 + 任务自动蒸馏 |
| 交付形态 | SaaS 订阅 | 模型底座 | **开箱即用的数字员工队伍平台** |

**一句话：模型平台解决"有没有大脑"，我们解决"有没有一支能干活、管得住的队伍"。两者是互补层，不是竞争关系。**

## 七、落地路径与拓展规划

### 第一阶段：单点试点（资源到位即可启动）
1–2 名数字员工（后端/前端各一）+ 1–2 个真实迭代任务，shadow 级全程盯梢，跑通企业内 GitLab/Jira/CI 链路，产出效能基线数据。

### 第二阶段：班组试点
扩展到 4–6 名数字员工的班组作业，依赖编排交付跨模块需求；盯梢等级按表现渐进放权；技能库随任务自动沉淀启动运转。

### 第三阶段：组织级推广
- 岗位体系横向扩展（测试/DevOps/安全合规等更多工种）；
- 老系统 UI 垫片批量接入（无 API 存量系统）；
- 数字员工 7×24 值守场景（夜间构建修复、值班巡检、批量技术债清理）。

### 平台化方向（中期）
- **执行体容器化**：按任务动态起容器/跨机调度，数字员工并发规模弹性扩展（执行单元已是无状态设计，改造路径明确）；
- **计划项级精细编排**：一个任务内多工种步骤逐项选岗注入；
- **技能生态**：跨团队技能库共享与推荐、技能市场机制。

## 八、成功的关键：不是替代人，而是重组产线

数字AI研发人员平台的价值主张可以浓缩为三条：

1. **把"必须在场的人"从重复环节里解放出来**——人做判断和创造，数字员工做执行和值守；
2. **让组织的研发经验第一次变成可积累的资产**——每个任务都在给技能库喂料，越用越强；
3. **用工程化的闸门而非信任去拥抱 AI**——放权三级、审计 hash 链、能力边界，让科技风控敢签字，AI 才能真正进入产线。
