# 试点部署手册（runbook）

> 面向运维/交付工程师：银企业内网试点机从零到数字员工跑通一条任务的完整操作手册。
> 交付前可在有网开发机一键预演本手册 1–4 步：`node scripts/rehearsal.mjs`（P15）。

## 0. 交付物与前置条件

**交付物**：`ddw-offline-<date>.tar.gz`（源码 + pnpm store + install.sh + OFFLINE.md），拷贝介质带入内网。

**试点机前置**：

| 项 | 要求 | 检查 |
|---|---|---|
| Node.js | ≥ 20.5（node:sqlite 内置；推荐 22 LTS） | `node -v` |
| pnpm | ≥ 9（无则从有网机下载 tgz 带入安装） | `pnpm -v` |
| bash | 任意现代版本 | — |
| 磁盘 | 安装 + 测试临时文件数百 MB | `df -h .` |
| 白名单命令 | git / node / npm / npx / python3 在 PATH（数字员工执行环境依赖） | doctor 会检 |
| 端口 | 控制台端口（默认 3100）未被占用 | `ss -tlnp | grep 3100` |

## 1. 安装

```bash
tar -xzf ddw-offline-<date>.tar.gz -C ddw && cd ddw
bash install.sh
```

install.sh 依次：Node 版本前置检查（< 20.5 首错即拦）→ `pnpm install --offline --frozen-lockfile --store-dir ./pnpm-store`（全程不出网）→ `pnpm -r test` 冒烟（299 用例全绿即安装成功，不监听端口）。失败时按脚本给出的排查提示处理（见 §7）。

## 2. 凭据配置（密文落盘，主密钥不落盘）

```bash
export DDW_CRED_KEY=$(node packages/console-api/src/cli.ts cred key)   # 生成一次，持久化到 /etc/ddw/env
node packages/console-api/src/cli.ts cred enc '<模型集群真实apiKey>'     # 输出 enc:v1:... 粘贴进 runtime yaml
```

- 主密钥持久化：`echo 'DDW_CRED_KEY=<key>' > /etc/ddw/env && chmod 600 /etc/ddw/env`（systemd 经 EnvironmentFile 注入）
- runtime yaml 的 `apiKey` 明文/密文两用（`enc:v1:` 前缀即 AES-256-GCM 解密）；密文缺主密钥/错 key/篡改 = 启动即失败
- 员工在各系统的账号凭据按同一方式配置（GitLab token / Jira 密码等）

## 3. 巡检（启动前体检）

```bash
node packages/console-api/src/cli.ts doctor --data ./data \
  --runtime examples/console-runtime.example.yaml --probe
```

`--probe` 会探测模型集群连通（内网可达性，任何 HTTP 响应都算可达）。全部 ✓ 再启动；任一 ✗ 按 §7 处置。

## 4. 启动（systemd 常驻）

```bash
sudo cp scripts/ddw-console.service /etc/systemd/system/   # 按注释改路径/用户
sudo systemctl daemon-reload
sudo systemctl enable --now ddw-console
sudo systemctl status ddw-console
```

手工前台试跑（验证配置后再交 systemd）：启动命令见 [README 快速开始](../../README.md)。启动后浏览器打开控制台端口应看到任务池/数字员工名册视图。

## 5. 冒烟验收清单（交付签字依据）

| # | 验收项 | 操作 | 通过标准 |
|---|---|---|---|
| 1 | 安装冒烟 | install.sh | pnpm -r test 全绿 |
| 2 | 巡检 | doctor --probe | 全部 ✓，退出码 0 |
| 3 | 服务常驻 | systemctl status | active (running)；重启机器后自启 |
| 4 | 控制台可达 | 浏览器开控制台端口 | 任务池/名册/审计页可打开 |
| 5 | 任务链路 | 粘贴任务包 yaml 固化 → 数字员工接单执行 | 直播时间线有思考/工具事件；任务 done |
| 6 | 盯梢闭环 | shadow 级员工任务申报节点 | 待审可见 → 放行后继续 / 驳回后按意见重报 |
| 7 | 审计完整 | `GET /api/audit?integrity=1` | `ok: true`（hash 链成链） |
| 8 | 崩溃隔离（可选） | `--exec-mode fork` 下制造员工异常 | 任务落 failed、控制台进程存活 |

## 6. 故障排查表（doctor ✗ 项 → 处置）

| ✗ 项 | 可能原因 | 处置 |
|---|---|---|
| Node 版本 | < 20.5 | 升级 Node（22 LTS）；离线环境从有网机带 tgz |
| 数据目录可写 | 权限/路径不存在 | `chown -R ddw:ddw <dataDir>`；检查 systemd WorkingDirectory 与 --data 一致 |
| 存储与审计 hash 链 | 链校验失败 = 数据可能被篡改/手工改过 | **不要删数据**：备份目录，导出事件排查 brokenAt 断点，评估是否接受重置（回滚见 §8） |
| 运行时配置与凭据 | yaml 语法/字段错；密文缺主密钥；DDW_CRED_KEY 未注入 | 按报错修 yaml；确认 `/etc/ddw/env` 存在且当前 shell 有 export |
| 主密钥 | 格式不对（须 64 位 hex） | 重跑 `cred key` 生成；**注意换 key 后旧密文解不开，需重新 enc** |
| bash 白名单命令 | PATH 缺 git/node 等 | 安装缺失命令或修正 PATH；systemd 场景注意 service 的 PATH 与登录 shell 不同 |
| 模型集群连通 | 网络/地址/防火墙 | curl baseUrl/models 验证；找网络组开通到模型集群的端口 |
| install.sh 冒烟失败 | 依赖不完整/磁盘满 | 见脚本内排查提示（store 完整性 / df -h / node -v） |

## 7. 数据与回滚

- **数据目录**（`--data`，默认 ./data）：SQLite 库（任务池 + 审计事件）+ 数字员工 session JSONL。**升级/重装前先备份**：`tar -czf ddw-data-backup-$(date +%F).tgz <dataDir>`。
- **回滚**：停服务 → 换回旧版本包（重新解包 + install.sh）→ 还原数据目录 → 起服务。审计链数据向前兼容，回滚不破坏链。
- **演练失败现场**：`node scripts/rehearsal.mjs --keep` 保留临时目录；失败报告落 `dist-offline/rehearsal-failed.log`。

## 8. 试点硬排除项（不做/不支持）

- 验证码 / SSO / UKey 系统的 UI 垫片（P14 硬排除；此类系统走人工或等系统侧 MCP）
- 对公网的一切访问（模型/工具全部内网私有化）
- 自动安装 systemd 单元（样例由运维评审后手工部署）
